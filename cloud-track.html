Cloud is infrastructure and architecture

The cloud is two things at once.

  • Rented infrastructure. Servers, disks and networks you do not own. Setting them up, securing them, automating them and running them is infra work.
  • Ready made building blocks. Load balancers, queues, caches, databases, serverless functions and AI models. These are the boxes you draw in a system design.

It also changes architecture decisions. Regions and zones shape how you design for failure. Managed services change what you run yourself. Pay per use turns cost into a design choice. And security is shared with the provider.

This track teaches both sides with AWS as the main example, because it is the most used cloud and the SAA-C03 exam is a common goal. Level 7 maps everything to Microsoft Azure and Google Cloud.

How this track works

  • Lessons. Each one has the idea in one minute, an animated diagram, key words, how it works, real cases, trade-offs, mistakes, a security lens, a quiz, interview questions with feedback and a practice desk.
  • Practice pages. Every level ends with mixed questions. Spot the bug, the risk, the GRC gap, the benefit, the fix and the workaround.
  • Designs by tier. Level 8 designs a tier 0 foundation and tier 1 to tier 4 applications, each secure, with the right level of resilience and cost.
  • Links to the rest of the site. Concepts explain the ideas behind each service. Infra has hands on Git, Docker, Kubernetes and Terraform. Protocols animate DNS, TLS, BGP and more.
