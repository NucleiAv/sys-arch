Load balancers and reverse proxies

A load balancer is the traffic police in front of your servers. It spreads requests, skips dead servers and hides your machines from the internet.

The idea in one minuteWatch it, step by stepWords you needHow it worksReal life scenariosTrade-offsCommon mistakesSecurity lensPractice. Check yourselfPractice. Interview questionsPractice deskGo deeper

The idea in one minute

Once you have many servers, someone must decide which server gets each request. That is the load balancer. Users only ever see one address, the load balancer's. Behind it, servers can come and go.

A load balancer also checks on servers all the time with health checks. If a server stops answering, it gets no more traffic until it recovers.

Think of it like this

At a big bank, a greeter at the door sends each customer to a free counter. If a counter closes, the greeter stops sending people there. Customers never need to know which counters are open.

Watch it, step by step

Press Next or Play. Each step lights up one part and moves the requests. Arrow keys move steps after you click the diagram.

Words you need

Load balancer
Spreads requests over many servers and skips unhealthy ones.
Health check
A small request the load balancer sends to each server to see if it is alive and ready.
Reverse proxy
A server that takes requests on behalf of your servers. It can add TLS, caching, compression and limits. Nginx is a common one.
Layer 4
Balancing by IP and port only. Very fast, does not read the request.
Layer 7
Balancing by reading the HTTP request, so it can route /api and /images to different servers.
TLS termination
The load balancer decrypts HTTPS so servers behind it do not have to.
Connection draining
Letting a server finish its current requests before it is removed.

How it works

How it picks a server

MethodHow it worksGood for
Round robinTake turnsServers and requests that are all alike
Weighted round robinBigger servers get more turnsMixed server sizes
Least connectionsPick the server with the fewest open requestsRequests that take very different times
IP or key hashSame user always goes to the same serverCaches per server, sticky needs

Layer 4 or layer 7

A layer 4 balancer only sees addresses and ports. It is very fast and handles any kind of traffic. A layer 7 balancer reads the HTTP request. It can send /video to video servers, check cookies, and retry on another server. Most web apps use layer 7.

Who balances the balancer?

A single load balancer is a single point of failure. Real setups run at least two, sharing a floating address, or use a managed cloud load balancer that is redundant by design. DNS can also spread users across several load balancers or regions.

Key point

A deeper health check is not always better. If /health also checks the database, a database hiccup marks every server unhealthy at once and the whole site goes down. Check what the server itself controls.

Real life scenarios

A deploy takes the site down for a minute

The team restarted all servers at once. With connection draining and rolling deploys, servers are removed one at a time, finish their work, update, pass a health check and rejoin. Users notice nothing.

One slow server drags everyone down

Round robin kept sending a fair share to a server with a failing disk. Every third request was slow. Least connections, plus taking the server out when its latency was high, fixed it.

A health check that killed a site

A health endpoint checked the database. When the database had a 10 second hiccup, every server failed its check and the load balancer removed all of them. The site was down long after the database recovered.

ChoiceGood atCosts you
Round robinSimple and fair for equal requests.Ignores how busy each server really is.

Common mistakes

  • Running only one load balancer.
  • Making health checks depend on shared parts like the database.
  • Restarting every server at the same time during a deploy.
  • Forgetting that WebSocket connections stay open for a long time, so new servers get little traffic until clients reconnect.

Security lens

The load balancer is usually the front door, so it carries many controls.

  • TLS termination with modern settings and automatic certificate renewal.
  • A web application firewall for common attacks and bot rules.
  • Rate limits and connection limits against floods.
  • Trust X-Forwarded-For only from your own proxies. Otherwise attackers fake their IP.
  • Hide internal server names and versions in responses.
