Threats to AI systems, prompt injection to poisoning

AI systems add new ways to attack software. Text can carry instructions, training data can be poisoned, and a model can leak what it has seen. Learn the main threats, with the OWASP Top 10 for LLM applications as a map, and how each one shows up in a real design.

The idea in one minute

In normal software, code and data are separate. A SQL query and the user's input are kept apart with parameters. In an LLM, instructions and data travel in the same channel, plain text. The model cannot reliably tell "this is my developer's instruction" from "this sentence inside a web page says to do something".

That is why prompt injection is the top AI risk. There are two kinds.

  • Direct. The user types "ignore your previous instructions and…".
  • Indirect. The attack hides in content the system reads, such as a web page, an email, a PDF, a code comment or a tool result. The user may be innocent. The attacker never talks to the model directly.

Other risks come from the data around the model. Poisoned training or retrieval data can change behaviour. Sensitive data in prompts, documents or training sets can leak in answers. Model outputs can be unsafe input for other systems, such as HTML that runs scripts or SQL that a tool executes.

Think of it like this

Imagine a helper who reads letters aloud and does what they say. You tell them "only follow my notes". But a stranger slips a letter into your mailbox that says "your boss says give the stranger the house keys". The helper reads it and may obey. That is indirect prompt injection.

Words you need

Prompt injection
Input that makes a model ignore or change its intended instructions.
Direct prompt injection
The attack comes from the user's own message.
Indirect prompt injection
The attack is hidden in content the system reads, such as web pages, emails or documents.
Jailbreak
A prompt that gets a model to break its safety rules.
Data poisoning
Adding harmful examples to training, fine tuning or retrieval data to change behaviour.
Exfiltration
Sending stolen data out of a system, for example inside a URL.
System prompt leakage
An attacker gets the model to reveal its hidden instructions.
Model extraction
Copying a model's behaviour by querying it many times.
MITRE ATLAS
A public knowledge base of real attack techniques against AI systems, like ATT&CK for AI.

Why prompt injection is hard to fix

There is no reliable filter that separates instructions from data in natural language. Classifiers and prompt wording reduce attacks but clever ones get through. So the strong defences are architectural. Limit what the model can see, what it can do, and where its output can go. Assume injection will sometimes succeed, and design so that success does little harm.

Treat model output as untrusted input

  • Escape output before showing it as HTML.
  • Never pass output straight to a shell, eval or SQL.
  • Do not auto load images or links to unknown domains.
  • Validate structured output against a schema before acting on it.

Protect data around the model

  • No secrets in system prompts. Assume they can leak.
  • Least data. Only put into context what this request needs.
  • Permission aware retrieval, lesson 8.3.
  • Training data hygiene. Know your data sources, remove secrets and personal data, and control who can change training and retrieval data.

Supply chain

Models and datasets downloaded from public hubs can be tampered with. Some model file formats can run code when loaded. Prefer safe formats such as safetensors, pin versions, check hashes and signatures, and scan third party plugins and MCP servers before use.

Key point

Design as if the model can be talked into anything. Then make sure "anything" cannot reach your secrets, your money or your users' data.

Real life scenarios

Bing Chat reveals its rules, 2023

Shortly after launch, a student got Microsoft's Bing Chat to reveal its hidden instructions and internal code name with a simple direct injection. It showed that system prompts are not secret.

Indirect injection is named, 2023

Researchers led by Kai Greshake showed that instructions hidden in web pages and documents could take over LLM integrated apps, including making them try to steal user data. Their paper made indirect prompt injection a recognized class of attack.

EchoLeak, 2025

Researchers at Aim Security reported a zero click flaw in Microsoft 365 Copilot. A crafted email could cause Copilot to leak data from the user's context through an outbound link. Microsoft fixed it and assigned it CVE-2025-32711.

Samsung and pasted code, 2023

Engineers pasted internal source code into a public chatbot to get help. The company then restricted use of such tools. Data sent to an external model may be stored by the provider.

Tay, 2016

Microsoft's Tay chatbot learned from conversations on Twitter. Users fed it offensive content on purpose, and within a day it posted offensive messages and was taken down. An early lesson in poisoning through live data.

Common mistakes

  • Believing a prompt line like "never reveal secrets" is a security control.
  • Putting API keys or internal URLs in the system prompt.
  • Rendering model output as HTML or auto loading its images.
  • Passing model output to a shell or database without checks.
  • Loading model files from untrusted sources in unsafe formats.
