Route 53, CloudFront, Global Accelerator, WAF and Shield

Before a request reaches your servers, it meets DNS, a content delivery network and edge protection. Learn the Route 53 routing policies, how CloudFront caches and protects origins, when to use Global Accelerator instead, and how WAF and Shield stop attacks at the edge.

The idea in one minute

Route 53 is AWS's DNS service. It answers "what address is shop.example.com?" and it can answer differently depending on rules, called routing policies, and on health checks. Route 53 has a 100 percent availability service level agreement.

CloudFront is AWS's content delivery network. It caches content in edge locations near users, so images, scripts and even API responses come from a city nearby instead of your region. It also hides and protects your origin.

Global Accelerator gives you two fixed anycast IP addresses. Users connect to the nearest edge location, and traffic then rides AWS's private global network to your app. It speeds up and stabilizes traffic that cannot be cached, such as gaming, voice or TCP and UDP services, and fails over between regions in seconds.

AWS WAF is a web application firewall. It filters HTTP requests with rules, such as blocking SQL injection patterns, bad bots or too many requests from one IP. AWS Shield protects against distributed denial of service attacks. Shield Standard is on for every customer at no extra cost. Shield Advanced adds more protection, a response team and cost protection.

Think of it like this

Route 53 is the phone book that can send callers to the nearest open branch. CloudFront is a chain of small shops that keep copies of popular items near every neighbourhood. Global Accelerator is an express road from your street to the main shop. WAF and Shield are the guards at the door.

Words you need

Route 53
AWS's DNS service with health checks and routing policies.
Alias record
A Route 53 record that points to AWS resources, works at the zone apex, and has no charge for queries to AWS resources.
Health check
Route 53 tests an endpoint and stops sending traffic to it if it fails.
CloudFront
AWS's content delivery network, caching at edge locations.
Origin
Where CloudFront fetches content on a cache miss, such as S3 or a load balancer.
Origin access control
Lets only your CloudFront distribution read a private S3 bucket.
Global Accelerator
Two static anycast IPs that route users over AWS's network to the best healthy endpoint.
AWS WAF
A web application firewall with rules for HTTP requests.
AWS Shield
DDoS protection. Standard is free for all. Advanced is a paid upgrade.

CNAME versus alias. A CNAME cannot be used at the zone apex, such as example.com. An alias can, and points to AWS resources like CloudFront, load balancers and S3 websites.

CloudFront essentials

  • Cache behaviours per path, such as long caching for /images/* and no caching for /api/*.
  • Origin access control keeps S3 buckets private.
  • Signed URLs or signed cookies for paid or private content.
  • TLS with a free ACM certificate, which must be in us-east-1 for CloudFront.
  • Invalidations remove cached files early, but versioned file names are cheaper and faster.

WAF and Shield

  • WAF attaches to CloudFront, ALB, API Gateway, AppSync and Cognito.
  • Start with AWS managed rule groups, such as the core rule set and known bad inputs, then add rate based rules and bot control.
  • Shield Standard defends common network and transport layer attacks for everyone. Shield Advanced adds application layer DDoS help, a response team and protection from scaling costs during an attack.
Key point

Put CloudFront and WAF in front of public apps, keep origins private, and let DNS health checks steer traffic away from failures.

Real life scenarios

The 2.3 Tbps DDoS, 2020

AWS reported that Shield mitigated a DDoS attack peaking at 2.3 terabits per second in February 2020, a reflection attack using CLDAP servers. Customers behind AWS's edge did not have to absorb it themselves.

The bucket behind the CDN

A company served files through CloudFront but left the S3 bucket public too. Attackers skipped the CDN and its WAF and downloaded everything directly. Origin access control and a private bucket closed the gap.

Failover by DNS

A company used Route 53 failover records with health checks for its primary and standby regions. During a regional incident, DNS moved users to the standby within minutes, limited mainly by DNS caching and the TTL.

Common mistakes

  • Leaving the S3 origin public behind CloudFront.
  • Using a CNAME at the zone apex.
  • Very long DNS TTLs on records you may need to fail over.
  • No WAF rate limits on login and checkout.
  • Invalidating the whole cache on every deploy instead of versioning file names.

Security lens

The edge is where most attacks first arrive. Use WAF managed rules plus rate based rules on sensitive paths, keep origins reachable only from CloudFront, for example with origin access control for S3 and a secret header or the CloudFront managed prefix list for load balancers, enforce HTTPS, and log WAF and CloudFront requests for investigations.
