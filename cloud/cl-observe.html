CloudWatch, CloudTrail, Config, X-Ray and Systems Manager

You cannot run what you cannot see. Learn which AWS service watches what, metrics and logs, API calls, configuration changes and traces, how to build alarms that matter, and how Systems Manager lets you operate servers without SSH.

The idea in one minute

Several AWS services watch different things. People often mix them up, so learn them as a set.

  • CloudWatch watches performance and health. Metrics such as CPU and request counts, logs from apps and services, alarms that fire on thresholds, and dashboards.
  • CloudTrail records who did what. Every API call, such as "user Asha deleted bucket X at 10:42 from this IP".
  • AWS Config records what changed in configuration and checks resources against rules, such as "every bucket must block public access".
  • AWS X-Ray, and CloudWatch's application monitoring features, show traces, the path of one request across services.
  • Systems Manager helps operate servers. Session Manager for shell access without SSH, Patch Manager, Run Command and Parameter Store.

These map to Concepts lesson 4.2. Metrics tell you something is wrong, traces tell you where, logs tell you why, and CloudTrail tells you who changed something.

Think of it like this

CloudWatch is the car's dashboard with speed and warning lights. CloudTrail is the security camera recording who got in and what they touched. Config is a checklist that inspects the car every day and notes any change. X-Ray is a map of the trip that shows where you got stuck.

Words you need

CloudWatch metrics
Numbers over time, such as CPU, latency or queue length.
CloudWatch Logs
Stores and searches log lines from apps and AWS services.
CloudWatch alarm
Fires when a metric crosses a threshold, and can notify or act.
CloudTrail
Records API calls in your account, who, what, when and from where.
Data events
CloudTrail records of data access, such as S3 object reads. Off by default because of volume.
AWS Config
Records resource configuration over time and checks it against rules.
X-Ray
Distributed tracing for requests across services.
Systems Manager
Tools to operate servers at scale, including Session Manager and Patch Manager.
Session Manager
Shell access to instances through IAM, with no open SSH ports, and logged sessions.

CloudTrail essentials

  • Event history keeps 90 days of management events for free in each region.
  • Create a trail to keep logs longer in S3, across all regions and, in an organization, all accounts.
  • Data events, such as S3 GetObject and Lambda invoke, are off by default. Turn them on for sensitive buckets.
  • Protect the log bucket with Object Lock, and enable log file integrity validation.

Alarms that matter

  • Alarm on user pain, latency, error rate and SLO burn, Concepts lesson 4.2.
  • Use composite alarms to reduce noise.
  • Add alarms for security events, such as root sign in, IAM policy changes and CloudTrail being stopped.

Operate without SSH

  • Session Manager for shell access with IAM control and full session logs.
  • Patch Manager with maintenance windows.
  • Run Command to run scripts across many instances.
  • Automation runbooks for common fixes.
Key point

CloudWatch tells you how it runs. CloudTrail tells you who did what. Config tells you how it is set up. You need all three.

Real life scenarios

CloudTrail in breach investigations

In most cloud incident investigations, CloudTrail is the first place responders look, to see which keys were used, from where, and what they called. Accounts without a long term trail often cannot answer those questions.

Config catches a public bucket

An AWS Config rule flagged a bucket that became public after a policy change. An automatic remediation set Block Public Access within minutes.

Retiring the bastion

A company replaced SSH bastion hosts with Session Manager. Port 22 closed everywhere, and every shell session was logged to S3 for audit.

Common mistakes

  • No CloudTrail trail beyond the 90 day event history.
  • CloudTrail logs in a bucket the same admins can delete.
  • Alarms on CPU instead of user facing symptoms.
  • Logs kept forever at full price.
  • Opening SSH to debug instead of using Session Manager.

Security lens

Logging is a security control. Use an organization trail to a separate log archive account, with Object Lock and integrity validation. Turn on data events for sensitive S3 buckets. Alert on root sign ins, policy changes, disabled security services and access key creation. Send logs to your SIEM, and make sure responders can read them during an incident, lesson 6.2.
