Tier 4. A nightly analytics batch on Spot, cheap and still secure

Some work can wait. A nightly report that runs late by a day hurts no customer. Design a cheap, re runnable batch pipeline on Spot Instances and S3, accept single AZ compute and slow recovery, and still keep the data locked down.

The ask

A retailer wants a nightly job that reads the day's orders, clicks and stock, joins them, and builds sales reports and a file for the marketing team. If a run fails, it can run again the next morning, or even the next day. Design it as a tier 4 system with the lowest sensible cost.

Pin down the requirements

What it must do

  • Copy daily exports from the store's databases and logs into a data lake.
  • Run transformation jobs and write curated tables.
  • Let analysts query the results with SQL.

How well it must do it

  • Best effort availability. RTO 2 days. RPO 1 day, since raw data can be exported again.
  • Finish by 8 am on most days.
  • Cost as low as possible.
  • Customer personal data must be protected and only shared in masked form.

Out of scope, say it out loud

  • Real time dashboards and machine learning models.

Do the math

Each night the job needs 100 instances for 4 hours. On Demand costs 0.40 dollars an hour per instance. Assume Spot saves 70 percent on average for this instance family, which varies. It runs 30 nights a month.

Key point

Cheap compute is safe here only because the jobs can be stopped and restarted. Make every step re runnable before you buy Spot.

The API

The pipeline has no public API. It is a set of scheduled steps.

01:00  export      databases -> s3://lake-raw/orders/dt=2026-11-27/
01:30  transform   raw -> curated, Spark on EMR Serverless or AWS Batch on Spot
05:30  publish     curated tables registered in the Glue Data Catalog
05:45  masked file s3://lake-share/marketing/dt=2026-11-27/ (no names, hashed ids)

Each step is a state in AWS Step Functions with retries and alerts.

The data model

ZoneHoldsAccess
RawExact copies of exports, partitioned by datePipeline only

SharedMasked extracts for marketingMarketing role, read only
Glue Data CatalogTable definitions and partitionsGoverned by Lake Formation

Watch it work

Press Next or Play. Each step lights up one part and moves the requests. Arrow keys move steps after you click the diagram.

The big picture

  1. Storage. An S3 data lake with raw, curated and shared zones, SSE-KMS, Block Public Access, lifecycle rules to cheaper classes, and partitions by date.
  2. Compute. EMR Serverless, AWS Glue jobs, or AWS Batch on Spot. Many instance types and a Spot allocation strategy that favours capacity. Single AZ is acceptable for compute, while S3 already stores data across AZs.
  3. Orchestration. Step Functions with retries, timeouts, and an alert if the run is not done by 7 am.
  4. Re runnable steps. Each step reads one date partition and overwrites its own output partition, so running it again gives the same result.
  5. Catalog and access. Glue Data Catalog with Lake Formation permissions down to columns and rows. Analysts use Athena with workgroup limits on data scanned.
  6. Recovery. If the account or region has a problem, rerun from the source exports later. Raw data is versioned and replicated only if the business asks.

Deep dives

Why Spot fits here

Spot uses spare EC2 capacity at a large discount but can be reclaimed with two minutes notice. The job has no customers waiting and can retry, so interruptions cost minutes, not money or trust.

Make work small and restartable

Split the job into many small tasks, checkpoint long ones, and write outputs to a fresh partition before swapping it in. Then an interruption or a full rerun is safe.

Lower tier, same data rules

The data lake holds the same customer data as tier 1 systems. Lake Formation, masking, encryption and audit apply in full. Tier is about availability, not about how carefully data is handled.

Athena cost control

Athena charges by data scanned. Parquet files, partitions and workgroup limits keep a careless query from scanning the whole lake.

Security and abuse

  • Lake Formation for table, column and row permissions. No direct S3 access for analysts.
  • Personal data columns tagged and masked or hashed in curated and shared zones.
  • SSE-KMS with a key per zone. The marketing role cannot decrypt raw data.
  • VPC endpoints for S3 and Glue, workers in private subnets with no internet.
  • Job roles limited to their input and output paths.
  • CloudTrail data events on the raw bucket, Macie scans for unexpected personal data in shared zones.
