Block, file and object storage, and S3 storage classes

AWS has three kinds of storage, block, file and object, and S3 alone has several storage classes with very different prices. Learn which to pick, how lifecycle rules move data to cheaper classes, and how versioning and Object Lock protect data from mistakes and ransomware.

The idea in one minute

There are three kinds of cloud storage.

  1. Block storage, EBS. A virtual disk attached to one EC2 instance, like a laptop's drive. Fast, for operating systems and databases. An EBS volume lives in one AZ.
  2. File storage, EFS and FSx. A shared folder many servers can mount at once over the network. EFS works with Linux over NFS and spans AZs. FSx offers Windows file shares, Lustre for high performance computing, NetApp ONTAP and OpenZFS.
  3. Object storage, S3. Files called objects in buckets, reached by an API over HTTPS. Practically unlimited, designed for 99.999999999 percent durability, eleven nines, for data in most classes. Great for images, backups, logs and data lakes.

S3 has storage classes. Data you read every day belongs in S3 Standard. Data you rarely read can live in cheaper classes, and archives can go to Glacier classes for very little, if you can wait or pay to get them back. Lifecycle rules move objects between classes automatically as they age.

Think of it like this

Block storage is your own desk drawer, fast but only yours. File storage is a shared filing cabinet in the office. Object storage is a huge warehouse where every box has a label, you ask for a box by name, and old boxes can move to a cheaper warehouse far away.

Words you need

EBS
Elastic Block Store. Network attached disks for EC2, in one AZ.
Instance store
Very fast disks physically attached to the host. Data is lost when the instance stops.
EFS
Elastic File System. A shared NFS file system for Linux that spans AZs.
FSx
Managed file systems, for Windows File Server, Lustre, NetApp ONTAP and OpenZFS.
S3
Simple Storage Service. Object storage in buckets, reached over HTTPS.
Storage class
A tier of S3 with its own price, access cost and retrieval time.
Lifecycle rule
A rule that moves or deletes objects as they age.
Versioning
Keeps every version of an object, so overwrites and deletes can be undone.
Object Lock
Write once, read many protection that stops deletion until a retention date.
Snapshot
A point in time copy of an EBS volume, stored in S3 behind the scenes.

How it works

Block, file or object?

NeedChoose
Boot disk or a database on EC2EBS, gp3 for most, io2 for high and steady IOPS

EBS in short

  • gp3 is the default general purpose SSD, with a baseline of 3,000 IOPS and 125 MB per second that you can raise.
  • io2 Block Express for demanding databases.
  • st1 and sc1 are cheaper hard disk types for big sequential reads.
  • Volumes live in one AZ. Copy snapshots to move or protect data.

Deleting an object before the minimum duration still charges for the full minimum.

Protecting S3 data

  • Block Public Access at the account level, on by default for new buckets since 2023.
  • Versioning to undo overwrites and deletes, plus MFA delete for extra care.
  • Object Lock for write once, read many retention. Governance mode can be overridden by users with special permission. Compliance mode cannot be overridden by anyone until the date passes.
  • Replication to another region or account for disaster recovery.

Moving data in and out

DataSync copies large file sets online, Storage Gateway connects on premises apps to S3, Transfer Family offers SFTP into S3, and the Snow family ships physical devices when the network is too slow.

Key point

Put data where its access pattern fits, let lifecycle rules move it as it ages, and protect anything important with versioning, replication and Object Lock.

Real life scenarios

S3 strong consistency, 2020

In December 2020 AWS made S3 strongly consistent for all reads after writes and lists, at no extra cost. Before that, a read right after an overwrite could return the old version, which caught many developers out.

Lifecycle saves the logs bill

A company kept years of logs in S3 Standard. A lifecycle rule moving logs to Glacier classes after 90 days and deleting them after the legal period cut that storage cost by most of its total.

Ransomware and immutable backups

Ransomware gangs try to delete backups first. Organizations that kept backups in a separate account with S3 Object Lock in compliance mode could restore without paying.

ChoiceGood atCosts you

Common mistakes

  • Keeping data only on instance store.
  • Moving small, often read objects to Glacier and paying retrieval fees.
  • Forgetting minimum storage durations.
  • Versioning on with no lifecycle rule for old versions, so cost grows forever.
  • Treating replication as a backup. A delete can replicate too, so add versioning and Object Lock.

Security lens

S3 is the most common place for cloud data leaks. Keep Block Public Access on at the account level, use bucket policies with least privilege, encrypt with SSE-KMS for sensitive data, enable access logging or CloudTrail data events, and use Macie to find sensitive data. Protect backups with Object Lock in a separate account.
