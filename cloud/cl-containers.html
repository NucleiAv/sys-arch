Containers on AWS, ECS, EKS, Fargate and ECR

Infra lessons 2.2 to 2.5 taught Docker and Kubernetes. Now run containers on AWS. Learn the difference between ECS and EKS, what Fargate removes, how images are stored and scanned, and how to pick between containers, serverless and plain servers.

The idea in one minute

A container packs an app with everything it needs, so it runs the same everywhere. To run many containers in production you need an orchestrator that starts them, restarts failures, spreads them over servers and connects them to load balancers.

AWS offers two orchestrators.

  • Amazon ECS, Elastic Container Service. AWS's own, simpler orchestrator. You describe a task definition and a service that keeps N tasks running.
  • Amazon EKS, Elastic Kubernetes Service. Managed Kubernetes. AWS runs the control plane, and you get the standard Kubernetes API and tools.

Both need compute to run on, and you have two choices.

  • EC2 launch type or node groups. Containers run on EC2 instances you manage.
  • AWS Fargate. Serverless compute for containers. You give CPU and memory per task or pod, and AWS runs it with no servers for you to patch.

Images are stored in Amazon ECR, a private registry that can scan images for known vulnerabilities.

Think of it like this

Containers are lunch boxes with the whole meal inside. ECS is the school's own simple lunch rota. EKS is the famous international rota system that many schools use. Fargate means the school hires a catering company, so nobody has to run the kitchen.

Words you need

ECS
Elastic Container Service. AWS's own container orchestrator.
Task definition
In ECS, the blueprint for containers, image, CPU, memory, ports, role and logs.
ECS service
Keeps a set number of tasks running and connects them to a load balancer.
EKS
Elastic Kubernetes Service. Managed Kubernetes control plane on AWS.
Fargate
Serverless compute for ECS tasks and EKS pods.
ECR
Elastic Container Registry. Private image storage with vulnerability scanning.
Task role
The IAM role a running container uses to call AWS.
App Runner
A simpler service that runs a web app from an image or source code with little setup.

Running containers well

  • Two roles. The task execution role lets ECS pull images and write logs. The task role is what your code uses. Keep them separate and small.
  • Logs to CloudWatch Logs or another log system.
  • Secrets from Secrets Manager or Parameter Store, injected at start.
  • Scan images in ECR and rebuild regularly with patched base images.
Key point

Pick the least operations heavy option that meets your needs. For many teams that is ECS on Fargate.

Real life scenarios

Fargate for a small team

A five person startup moved from hand managed Docker hosts to ECS on Fargate. They stopped patching servers entirely and deploys became one pipeline step.

EKS for a platform team

A large company standardized on Kubernetes across clouds and its own data centers. EKS let it use the same tools, Helm charts and policies on AWS.

The image with a critical CVE

ECR scanning flagged a critical vulnerability in an old base image. Because images were rebuilt weekly from patched bases, the fix shipped in the next routine release.

ChoiceGood atCosts you

EKSKubernetes standard and ecosystem.More complex, control plane fee.
FargateNo servers to manage.Higher unit price, fewer low level options.

Common mistakes

  • Choosing EKS without Kubernetes skills on the team.
  • One shared task role with broad permissions for every service.
  • Secrets in task definition environment values.
  • Images built once and never rebuilt.
  • No deployment circuit breaker or rollback.

Security lens

Containers add the image supply chain to your attack surface. Scan images, sign them, and allow only images from your registry. Give each service its own task role, run containers as non root, enable read only root file systems where possible, and use Kubernetes Pod Security Standards and network policies on EKS. Fargate gives each task its own isolation boundary, which reduces the impact of container escapes.
