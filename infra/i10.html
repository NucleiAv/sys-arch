The cloud and AWS basics, regions, IAM and EC2

The cloud lets you rent servers, storage and services by the minute. Learn how AWS is organized, who is responsible for what, how permissions work with IAM, and how to run a server with EC2.

The idea in one minute

Before the cloud, a company bought servers, waited weeks for delivery, and paid for them even when they sat idle. Cloud computing lets you rent computing over the internet. You start a server in a minute, pay for what you use and give it back when you are done.

Amazon Web Services, or AWS, is the largest cloud provider. Microsoft Azure and Google Cloud are the other big ones. The ideas in this lesson are the same in all three. Only the names change.

AWS has hundreds of services. You only need a few to start. IAM for permissions, EC2 for virtual servers, S3 for files, RDS for databases and VPC for networks.

Think of it like this

The cloud is like electricity. You do not build a power plant at home. You plug in and pay for what you use. AWS is one big power company with many kinds of sockets.

Words you need

Region
A geographic area with its own AWS data centers, such as ap-south-1 in Mumbai.
Availability zone
One or more separate data centers inside a region.
Shared responsibility model
AWS secures the cloud itself. You secure what you put in it, such as your data, access and settings.
IAM
Identity and Access Management. Controls who can do what in your AWS account.
IAM role
A set of permissions that a service or person can take on for a short time, without long lived keys.
Policy
A JSON document that allows or denies actions on resources.
EC2
Elastic Compute Cloud. Virtual servers called instances.
AMI
Amazon Machine Image. The template an EC2 instance starts from.
Auto Scaling group
Keeps a number of EC2 instances running and adds or removes them with load.
CloudWatch
AWS service for metrics, logs and alarms.
CloudTrail
AWS service that records every API call in your account, for audits.

How it works

AWS securesYou secure
Data center buildings and hardwareWho can log in and what they can do, with IAM
The network between data centersYour network rules, such as security groups

Your data, encryption and backups

IAM in plain words

  1. Lock the root user. Turn on MFA and do not use it for daily work.
  2. Give people access through IAM Identity Center or IAM users with MFA.
  3. Give programs a role, not access keys. An EC2 server gets a role through an instance profile. A GitHub Actions workflow gets a role through OIDC.
  4. Allow only what is needed, least privilege.

This policy allows reading files in one bucket.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::shop-images/*"
    }
  ]
}

EC2 in five steps

  1. Choose an AMI, such as Amazon Linux or Ubuntu.
  2. Choose an instance type, such as t3.micro for small tests or m7g.large for general work.
  3. Choose a network, subnet and security group.
  4. Attach a role and storage.
  5. Start it. For real services, use a launch template and an Auto Scaling group instead of single servers.

How you pay

OptionGood for
On-DemandPay by the second, no commitment. Tests and spiky work.
Savings Plans and Reserved InstancesCommit for 1 or 3 years for a big discount. Steady work.
SpotSpare capacity at a large discount. AWS can take it back with a 2 minute warning. Batch jobs and CI.
Key point

Set a budget alarm on day one. Many beginners get a surprise bill from a server or a NAT gateway they forgot to delete.

Real life scenarios

The root key on a laptop

A startup used root access keys in a script. A stolen laptop gave an attacker full control of the account. They moved to roles and turned off root keys.

Spot for CI

A team ran its build machines on Spot instances and cut that bill by more than half. When AWS took a machine back, the job simply retried on another one.

Trade-offs

ChoiceGood atCosts you
CloudNo upfront cost, scale in minutes, many managed services.Ongoing cost, needs cost and security discipline.
Own serversPredictable cost at a steady large scale, full control.Upfront cost, slow to grow, you run everything.
Single zoneCheapest and simplest.One zone failure stops you.
Multi zoneSurvives a zone failure.More cost, some data transfer charges.

Common mistakes

  • Using the root user for daily work.
  • Long lived access keys in code or on laptops.
  • Policies with "Action": "*" and "Resource": "*".
  • All servers in one availability zone.
  • No budget alarm.

Security lens

In the cloud, identity is the new perimeter.

  • Lock away the root user. Use MFA and never use it day to day.
  • Use IAM roles with least privilege, not long lived access keys.
  • Turn on CloudTrail in every region and send logs to a separate account.
  • Use IMDSv2 on EC2, which blocks many server side request forgery attacks on instance credentials.
  • Use AWS Organizations and service control policies to set guardrails for every account.
