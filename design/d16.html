Design a discussion forum with threads, votes and moderation

People start topics, reply in threads, vote, and moderators keep it civil. Like Reddit, Discourse, Stack Overflow or a community chat forum.

The ask

Build a forum with communities, threads and nested replies. Users vote on posts, see hot and new lists, search old threads, get notified about replies, and moderators remove spam and abuse. Most people only read.

Pin down the requirements

What it must do

  • Communities, threads and nested replies, up to 10 levels shown.
  • Up and down votes, with hot, new and top sorting.
  • Search over titles and posts.
  • Notifications for replies and mentions.
  • Moderation tools, reports, removal, bans and a spam filter.

How well it must do it

  • Thread pages load in under 300 ms, even for viral threads.
  • Reads far outnumber writes, plan for about 25 reads per write.
  • Vote counts can be a few seconds behind. Posts must never be lost.
  • Handle a sudden spike when a thread goes viral.

Out of scope, say it out loud

  • Private messages, live voice rooms, ads.

Do the math

10 million daily users. Each views 50 pages and writes 2 posts or comments a day. A post averages 1 KB with metadata. Use 100 thousand seconds in a day.

Key point

Heavy reads and light writes point to aggressive caching of thread pages and lists, a SQL store for posts, and async work for counts, search and notifications.

The API

GET  /v1/c/{community}/threads?sort=hot&after=cursor
GET  /v1/threads/{thread_id}?sort=top&depth=4
POST /v1/c/{community}/threads            { title, body }
POST /v1/threads/{thread_id}/posts        { parent_id, body }
POST /v1/posts/{post_id}/vote             { value: 1 | -1 | 0 }
POST /v1/posts/{post_id}/report           { reason }
GET  /v1/search?q=kafka+partitions&c=sysdesign

Nested replies use a materialized path, like 0001.0007.0003. Sorting by path returns a whole thread in tree order with one query. A relational database like PostgreSQL fits well, sharded by community when it grows.

The big picture

  1. Edge. A CDN serves pages to logged out readers, often most of the traffic.
  2. Forum service. Stateless servers behind a load balancer.
  3. Cache. Redis holds rendered thread pages, community lists and hot rankings. Invalidate or refresh on new posts.
  4. Primary store. PostgreSQL for communities, threads, posts and votes, with read replicas.
  5. Async work. A queue feeds vote counting, hot score updates, search indexing, notifications and spam checks.
  6. Search. Elasticsearch or OpenSearch, fed from the queue.
  7. Moderation. Report queues, automated filters and audit logs of every moderator action.

Deep dives

Hot ranking

A hot score mixes votes and age, so new posts with some votes beat old posts with many. One classic formula is the log of the net votes plus the post time divided by a constant, which makes 10 times more votes worth a fixed amount of freshness. Recompute scores in the background and keep the top few hundred per community in a Redis sorted set.

Nested replies

Materialized paths let you load a thread in tree order with one query. Load the top replies and a few levels deep, then load more on demand. For huge threads, page by top level reply.

Vote counting

Store each vote with a unique key on user and post, so a vote cannot count twice. Update counts in batches from a queue. Show counts that are a few seconds behind, which nobody notices.

Caching thread pages

Cache the page for logged out readers for a few seconds, which absorbs viral spikes. For logged in users, cache the shared thread data and add per user parts, like their own votes, separately.

Moderation at scale

Combine rate limits for new accounts, link filters, machine learning spam scores, user reports and human moderators. Every moderator action is logged with who, when and why.

Security and abuse

Forums are public, so abuse is normal.

  • Stored XSS. Posts contain user text shown to others. Render Markdown with a safe library and sanitize HTML. Add a Content Security Policy.
  • Spam and bots. Rate limit by account age and IP, filter links, and use CAPTCHAs on suspicious sign ups.
  • Vote manipulation. One vote per user per post with a unique key, plus detection of vote rings and fake accounts.
  • Authorization. Only the author or a moderator can edit or delete. Check on every request.
  • Moderator abuse. Log every moderator action and give users an appeal path.
  • Privacy and law. Handle deletion requests, and follow local rules on illegal content, such as notice and action duties in the EU Digital Services Act.
