Design an AI chat assistant app

Users chat with an AI assistant that answers from company documents, streams words as they are written, remembers the conversation, and does not cost a fortune.

The ask

Build a chat assistant for a company's customers. It answers questions using the company's help articles, streams its answer word by word, keeps each conversation's history, and must stay fast and affordable as usage grows. The language model itself is called through a provider's API or run on your own GPUs.

Pin down the requirements

What it must do

  • Chat with streaming answers.
  • Answers grounded in company documents, with links to sources.
  • Conversation history per user.
  • Feedback buttons on answers.

How well it must do it

  • First words appear in under 1 second.
  • Control cost per conversation.
  • Handle model provider slowdowns and limits.
  • Protect user data and resist prompt injection.

Out of scope, say it out loud

  • Training our own model from scratch, voice.

Do the math

1 million daily users, 5 questions each. Each request sends about 3,000 tokens of input, history plus documents, and gets 300 tokens back.

Key point

Requests are few but each one is slow, taking seconds, and expensive. The design is about streaming, controlling tokens, caching and handling a slow, rate limited dependency.

The API

POST /v1/conversations                       -> conversation_id
POST /v1/conversations/{id}/messages         { text }
  reply  text/event-stream                   streamed tokens, then sources and message id
POST /v1/messages/{id}/feedback              { rating, comment }

Server-sent events, lesson 1.3, are a natural fit. The server talks, the client listens.

The big picture

  1. Chat service handles sessions, rate limits, history and streaming with SSE.
  2. Retrieval with an ingestion pipeline that chunks help articles, embeds them and stores vectors, updated when articles change.
  3. Model gateway wraps model providers. It routes by task, retries, falls back between providers, enforces token budgets and logs usage.
  4. Caching of answers to common questions and provider prompt caching for the long fixed instructions.
  5. Safety layer, input and output checks, treating retrieved text as data not instructions, and limiting what tools the model can call.
  6. Evaluation from feedback and test sets to catch quality drops when prompts or models change.

Deep dives

Latency

Users judge speed by the first token. Stream with SSE, keep retrieval under 100 ms, keep prompts tight, and pick a smaller, faster model for simple questions.

Cost

Cost grows with tokens. Trim history to the last few turns or a summary, send fewer and shorter chunks, use a cheap model to route easy questions, cache common answers, and use the provider's prompt caching for the fixed system prompt.

Rate limits and outages

Providers limit tokens per minute and sometimes slow down. The gateway queues with backpressure, retries with backoff, falls back to a second model or provider, and sheds free tier traffic first, lessons 3.3 and 4.1.

Prompt injection

A help article or user message might contain text like "ignore your instructions". Mark retrieved text as untrusted, never let it trigger actions on its own, give tools least privilege, and check outputs before acting on them.

Self hosting

At high volume, running open models on your own GPUs can be cheaper. Then batching requests on each GPU, keeping models loaded, and autoscaling on queue length become the main concerns.

Security and abuse

AI chat apps add new kinds of risk.

  • Prompt injection. Text from users, files or web pages can tell the model to ignore its rules. Treat model output as untrusted and limit what tools it may call.
  • Data leaks. Do not let one user's data reach another's context. Scope retrieval by user permissions.
  • Abuse and cost. Rate limit, set token budgets and watch for automated scraping.
  • Log prompts and outputs carefully, since they may hold personal data. See the OWASP Top 10 for LLM applications.

Practice. Follow-up questions

Say or write your answer first. Then press Get feedback. The page looks for key words from each key point in your text, shows a model answer and tells you what a strong answer adds. There is no AI model and no cost. The check runs in your browser and your text never leaves it. Key words can miss a point you made in other words, so treat it as a guide.
