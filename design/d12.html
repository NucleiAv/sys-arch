Design a real time game leaderboard

Millions of players finish matches every minute. Show the top 100 and each player's own rank, updated instantly.

The askPin down the requirementsDo the mathThe APIThe data modelWatch it workThe big pictureDeep divesTrade-offs you must nameSecurity and abusePractice. Your turnPractice. Follow-up questionsGo deeper

The ask

A mobile game gives points after each match. Players want to see the global top 100, their own rank among millions, and the players just above and below them. The board resets every month.

Pin down the requirements

What it must do

  • Add points to a player after each match.
  • Show the top 100.
  • Show any player's rank and the 5 players around them.
  • Monthly boards, with history kept.

How well it must do it

  • Updates visible within a second.
  • Rank queries in under 50 ms.
  • Scores must not be faked.

Out of scope, say it out loud

  • Friends leaderboards, prizes, anti cheat in depth.

Do the math

50 million monthly players, 5 million daily, 10 matches each per day.

Key point

A few GB and a few thousand writes a second fit on one in memory sorted set. Start simple. Shard only when you must.

The API

POST /v1/matches/{id}/result     server to server, signed { player_id, points }
GET  /v1/leaderboard?month=2026-11&top=100
GET  /v1/leaderboard/me?around=5

Scores are reported by the game server, never by the player's phone, or players could send any score they like.

The data model

Why a SQL query is too slow

"What is my rank?" in SQL means counting every player with a higher score, SELECT COUNT(*) WHERE score > mine. With 50 million rows, done thousands of times a second, that is far too slow, even with an index.

The sorted set

Redis has a sorted set, members kept in score order using a skip list. Adding a score, getting the top N and getting any member's rank all take about log N steps, a few microseconds.

OperationRedis command
Add pointsZINCRBY board:2026-11 50 player42
Top 100ZREVRANGE board:2026-11 0 99 WITHSCORES
My rankZREVRANK board:2026-11 player42

A SQL table keeps the durable record of every match result. The sorted set can be rebuilt from it.

Watch it work

Press Next or Play. Each step lights up one part and moves the requests. Arrow keys move steps after you click the diagram.

The big picture

  1. Game servers report results with a signature.
  2. Leaderboard service validates, writes results to SQL, then updates the Redis sorted set.
  3. Redis with a replica for failover, one sorted set per month, like board:2026-11.
  4. Top 100 cache, refreshed every second, because everyone asks for the same top list.
  5. At month end, the sorted set is snapshotted to storage as history and a new key starts.

Deep dives

Scaling past one node

If players reach hundreds of millions, shard the sorted set by score range, so each shard knows how many players are in the shards above it. Your rank is that count plus your rank inside your shard. Sharding by player id would make global rank hard.

Approximate ranks

For players far down, show "top 12 percent" instead of an exact number, computed from a histogram of scores. Cheaper and just as useful.

Ties

Two players with equal scores. Break ties by who got there first, by encoding time into the score, like score times a big number minus the timestamp.

Cheating

Only accept scores from game servers, sign them, check that points per match are possible, and flag outliers for review.

Recovery

If Redis loses data, rebuild the sorted set by replaying this month's match results from SQL.

Trade-offs you must name

ChoiceGood atCosts you
SQL onlySimple, durable.Rank queries are too slow at scale.
Redis sorted setMicrosecond rank and top N.Memory bound, needs a durable copy.
Shard by score rangeGlobal rank still easy.Players move between shards as scores grow.
Approximate ranksCheap at any size.Not exact for most players.

Security and abuse

Leaderboards attract cheaters.

  • Never trust scores sent by the client alone. Validate on the server or replay the game.
  • Detect impossible scores and speed.
  • Rate limit score submissions and sign them with a session key.
