Design maps and routing like Google Maps

You type a destination and in under a second you get a route, a time estimate and a map that scrolls smoothly. Learn how roads become a graph, how Dijkstra and A* find the fastest path, how precomputation makes it instant, and how live traffic changes the answer.

The ask

Users view a map, search for places and ask for the fastest driving route between two points, with a travel time that reflects current traffic. The route should update if traffic changes during the trip.

Pin down the requirements

What it must do

  • Show a map that pans and zooms smoothly.
  • Find the fastest route between two points, with an arrival time.
  • Use live traffic in routes and times.
  • Re route during navigation when a faster path appears.

How well it must do it

  • Route answers in under 1 second, map tiles in under 200 ms.
  • Millions of route requests an hour at peak.
  • Traffic data less than a few minutes old.

Out of scope, say it out loud

  • Place search ranking, public transport, walking and cycling routes, street view.

Do the math

A country's road network has about 20 million intersections and 50 million road segments. Each segment stores two node ids, a length, a speed and a few flags, about 40 bytes.

Key point

The graph fits in memory, so routing is about smart algorithms, not about storage. Map tiles, on the other hand, are many and small, so they are a caching problem.

The API

GET /v1/tiles/{z}/{x}/{y}.mvt                     vector map tile, cached by CDN
GET /v1/route?from=12.97,77.59&to=12.93,77.62&mode=drive&depart=now
    -> { duration_s, distance_m, polyline, steps: [...], traffic_used: true }
POST /v1/probes   anonymous speed samples from phones that opted in

The big picture

  1. Map data pipeline turns raw map data into a routing graph, and into tiles for each zoom level, offline.
  2. Tile service. Vector tiles in object storage behind a CDN. The phone draws them, so one tile set works for any style and language.
  3. Routing servers each hold the whole graph and precomputed shortcuts in memory. Route requests are spread across them by a load balancer.
  4. Traffic pipeline. Phones that opt in send anonymous speed samples. A stream processor, lesson 5.2, matches samples to road segments and averages speeds per minute, then publishes new edge costs to the routing servers.
  5. ETA model adjusts times using history, such as typical rush hour slowdowns, not only current speeds.
  6. Navigation sessions check the route every minute or two against new traffic and offer a faster one.

Deep dives

Dijkstra

Published by Edsger Dijkstra in 1959. It keeps a priority queue of nodes by distance from the start and always expands the closest. With non negative edge costs it always finds the shortest path. On a big road network it explores a huge circle around the start.

A star

Described by Hart, Nilsson and Raphael in 1968. It orders nodes by distance so far plus an estimate of the distance left. If the estimate never overestimates, it still finds the best path, but explores far fewer nodes. For travel time, straight line distance divided by the highest speed on the network is a safe estimate.

Precomputation

Long trips are still too slow even with A*. Methods such as contraction hierarchies precompute shortcut edges, so a query climbs to important roads quickly and explores only a few thousand nodes. Answers come in milliseconds.

Live traffic and shortcuts

Precomputed shortcuts assume fixed costs. Engines handle traffic with methods that can update costs quickly without a full rebuild, such as customizable route planning, which splits preprocessing into a slow map based part and a fast cost based part.

Tiles

The world is cut into square tiles at each zoom level. Zoom level z has 2 to the power z by 2 to the power z tiles. Tiles are prebuilt and cached on a CDN, so panning only fetches the few new tiles that come into view.

Security and abuse

Location data is very sensitive. Collect speed samples only from users who opted in, strip identities, cut traces into short pieces so a full journey cannot be rebuilt, and keep raw data briefly. Watch for fake traffic. In 2020 an artist walked through Berlin pulling a cart with 99 phones running Google Maps and made empty streets show as traffic jams. Look for many devices moving together in an unusual way.
